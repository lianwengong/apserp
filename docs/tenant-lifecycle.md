# 租户开通 / 停用

> 平台入口（无租户名登录）里的租户生命周期操作。租户管理员调用一律 403 —— 那是隔离红线。

## 1. 开通做了什么

`POST /api/admin/tenants`：

```json
{
  "code": "T003",
  "name": "杭州示例贸易有限公司",
  "shortName": "示例贸易",
  "industry": "批发",
  "templateTenantId": 1,
  "adminUserName": "admin",
  "adminPassword": "Tenant@2026a",
  "expireAt": null
}
```

三步，同一个事务：

1. **建租户行**：`plat.Tenant`（Code 唯一、默认启用、时区 `Asia/Shanghai`、币种 `CNY`）；
2. **克隆模板元数据**：`plat.usp_Tenant_Provision(模板租户, 新租户)` 复制
   模块 636 / 功能点 1436 / 菜单 1105 / 权限 2082 / 角色 9 / 数据对象 3 / 列表视图 / 表单 /
   页面 / 编码规则 / 字典 / 参数 / 业务规则（数字为当前实测，随配置增长）；
3. **建租户管理员**：`plat.User`（`MustChangePwd=1`，首次登录强制改密）+ 绑定**克隆出来的**
   `SYSADMIN` 角色。

> 第 3 步必须在克隆之后：角色是克隆出来的新 Id，先建用户会绑不上；
> 克隆过程本身**不复制用户**，所以「开通」必须自带建管理员，否则新租户没人能登录。

## 1.1 平台账号与租户解绑（V55）

平台账号**不属于任何业务租户**：库里单独有一个保留租户 `Id=0 / T000 平台运营`
（`plat.Tenant.IsPlatformTenant=1`），平台账号与平台菜单都挂在它下面。

- 平台登录（无租户名）拿到的是平台租户的会话：`tenantId=0` + `pf=true`；
- 平台菜单（`AppType=1`，43 条）复制了一份到平台租户，平台侧边栏不再依赖 T001；
- 租户列表接口过滤掉平台租户，看不到 T000；
- **因此停用任何业务租户（包括 T001）都不会被「平台账号所属租户」挡住**，
  唯一还保留的护栏是「至少保留一个启用的业务租户」；
- 平台租户本身不参与启停，调它的启停接口会明确报「平台租户只承载平台账号」。

演示账号：平台登录用 `platadmin / AsChain@2026`；租户登录用 `T001 / admin / AsChain@2026`。
`admin` 已摘掉平台标记，回归为 T001 的租户管理员。

## 1.2 编辑租户与管理员口令

`PUT /api/admin/tenants/{id}` —— **除租户编码外都能改**：

| 可改 | 说明 |
|---|---|
| 名称 / 简称 / 行业 | 展示信息 |
| 联系人 / 联系电话 | 用于对接与通知 |
| 用户上限 `MaxUsers` | 留空=不限制 |
| 到期时间 `ExpireAt` | 到期后由每日任务自动停用 |
| 备注 | 运维备注 |

编码不可改：它是库内唯一标识，改了会让审计、日志、外部对接全部对不上。
请求里即使带 `code` 也会被忽略（前端该字段是只读的）。

`POST /api/admin/tenants/{id}/admin-password` —— 维护**租户管理员口令**：

- 找该租户首个启用中的 `SYSADMIN` 账号（租户开通时自动创建的那个）；
- 写新哈希 + `MustChangePwd=1` + 清失败计数与锁定；
- 没有管理员账号时明确报「请先在用户与权限里创建」。

> 为什么放在租户管理里：实施/运维的场景是「客户把口令忘了」，
> 这时管理员在租户清单上直接重置最快，不用先跳到跨租户用户页再筛租户。

**每个业务租户一定有管理员**：

- 新租户开通时按填写的账号/口令建管理员，并绑定克隆出的 `SYSADMIN`；
  模板缺 `SYSADMIN` 角色时自动补建，不再报错；
- 存量租户（如种子 T002）由 `V56` 补齐：建 `admin` 占位账号 + 绑定 `SYSADMIN`，
  占位口令是随机哈希（不可登录），必须由平台管理员在「管理员口令」里设一次；
- 即使迁移没覆盖到，「管理员口令」也会在发现没有管理员时**自愈补建** admin 再设口令。

## 2. 停用 / 启用

`PUT /api/admin/tenants/{id}/enabled`  `{ "enabled": false }`

- 只改 `plat.Tenant.IsEnabled`，**不动任何数据**，可逆；
- 停用立刻生效：该租户的登录返回 `{"code":3002,"message":"租户已停用"}`；
- 两条护栏：
  - 不能停用**当前平台账号所属**的租户（停完这个会话也会失去数据访问能力）；
  - 至少保留一个启用状态的租户。

## 3. 权限

| 调用方 | 结果 |
|---|---|
| 平台登录（`app=1` + `pf=true`） | 允许 |
| 租户登录（即使本租户 SYSADMIN） | 403「仅平台管理员可开通/停用租户，请使用平台登录」 |

## 4. 前端

平台入口 → 平台管理 → 租户与组织 → **租户管理**（`/#/admin/tenants`）：

- 列表：编码 / 名称 / 简称 / 行业 / 状态 / 创建时间 / 到期时间 / 操作；
- 「开通租户」弹窗：编码（字母开头 2-20 位）、名称、简称、行业、管理员账号（默认 admin）、
  初始口令（8-64 位，含字母与数字）、到期时间（可选）；
- 行内「停用 / 启用」带二次确认；成功后刷新列表并提示。

## 5. 边界与后续

- **不做物理删除**：`plat` 下指向 `plat.Tenant` 的外键有 731 条，删除需要逐表清理，风险高；
  停用即可让租户「消失」在业务上。真要清退，按运维流程离线处理。
- 到期时间只落库展示，**还没有到期自动停用**的定时任务。
- 模板租户目前固定用平台账号所在租户（默认 1）；接口支持传 `templateTenantId`，
  前端暂不暴露（避免误用半成品配置做模板）。
