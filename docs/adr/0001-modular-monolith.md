# ADR 0001：采用模块化单体，不采用微服务

- 状态：已接受
- 日期：2026-10-30

## 背景

系统为中型商贸公司的进销存平台，225 张表、563 个菜单，由 10 人团队以 AI 生成代码的方式开发。
业务特征是强一致（库存扣减、成本结转、往来核销都要求事务内完成）。

## 决策

采用**模块化单体**：单个 Spring Boot 应用、单个数据库、按业务域分包（plat/md/pur/sal/ret/mkt/omn/inv/tms/fin/pln），
域间通过 `*.api` 包（接口 + DTO）调用，用 ArchUnit 自动守护边界。

## 理由

1. 强一致业务：跨域操作（销售出库 → 库存扣减 → 应收生成）必须同一事务，微服务需分布式事务或最终一致，复杂度不成比例。
2. AI 生成代码：跨服务契约、序列化、重试是 AI 最容易写错、人最难复核的部分。
3. 团队规模：10 人维护十个服务不现实，运维成本高于收益。
4. 演进路径：单体内保持包边界，未来若某域确定要独立（如商城），可整包拆出。

## 后果

- 部署只有一个单元，发布即全量（对内部系统可接受）。
- 需要严格的架构守护，否则包边界会腐化成大泥球。
- 水平扩展以应用实例为单位，不能按域独立扩容。
