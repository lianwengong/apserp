# 功能模块 / 子系统 / 终端 / 菜单 —— 关系说明

> 目的：把四个容易混为一谈的概念分开，说明它们在**数据库里怎么存**、**运行时怎么串**、
> **哪些约束由服务端强制**，以及现在的实际数据形态。
>
> 数据取自开发库 `APSErpV3`（V42 之后），数字都是实际 `SELECT COUNT(*)` 的结果。

---

## 1. 一句话定义

| 概念 | 是什么 | 不是什么 | 代码位置 |
|---|---|---|---|
| **子系统** | 交付与验收单位：有独立负责人、验收清单、上线开关。按「平台 / 终端 / 业务 / 集成 / 工程」五层划分（方案里 57 个） | 不是树节点，不参与运行时鉴权 | **当前系统没有这个实体**（仅存在于《开发方案》文档） |
| **功能模块** | 权限与配置的组织单位：模块树 + 功能点 + 动作链，产出 `MOD:`/`FUN:` 权限点 | 不是导航项，用户不会"点一个模块" | `plat.Module` / `plat.ModuleFunction` / `plat.FunctionAction` |
| **终端** | 渠道：PC / PDA / POS / 移动 / 小程序 / 其他（1..6） | 不是设备实例，是"哪类界面" | `plat.ModuleTerminal.TerminalType` |
| **菜单** | 给人点的导航入口：一棵独立树，挂在侧边栏；**每条菜单只属于一个终端** | 不等于模块（可以不绑模块，如分组、外链） | `plat.Menu` / `plat.MenuTerminal`（镜像） |

---

## 2. 三条强制规则（负责人定，服务端校验）

```
① 终端 ──配置──> 能用哪些功能模块        plat.ModuleTerminal（唯一来源）
② 菜单 ──必须指定──> 唯一终端             plat.Menu.TerminalType
③ 菜单绑定的模块 ──必须属于──> 该终端     保存时校验，不满足直接 400
```

规则 ③ 的报错长这样，直接告诉运维去哪修：

> 模块「0101 组织与门店」未在终端「PDA」启用，请先在「终端与功能」里为该终端启用这个模块

配套的两条保护：

- **停用保护**：把模块从终端上摘掉时，如果该终端下还有菜单指向它 → 拒绝并列出菜单名（否则会出现点开提示无权限的幽灵入口）；
- **父级补齐**：勾选子模块时自动启用其上级模块（否则该终端上模块树断链，菜单挂不到父节点）。

## 3. 关系总览

```
【概念层】
  子系统(57，交付/验收单位) ──1:n── 功能模块（谁负责交付哪些模块）

【配置层】
  功能模块（树：业务域 10 → 模块 62 → 功能节点 564）
     │ 1 : n
     ├──► 功能点(ModuleFunction) ──1:n──► 动作链(FunctionAction)
     │         └── 权限点  FUN:功能点编码
     └── 权限点  MOD:模块编码（每级一条）

  终端(1..6) ──n : n── 功能模块        plat.ModuleTerminal  ← 规则①：终端能用哪些模块
                              │
                              │ 规则③：菜单只能挂在「该终端已启用」的模块上
                              ▼
  菜单（必须属于唯一终端） ──n:1(可选)──► 页面(Page)
     │ 规则②：Menu.TerminalType
     └── 终端镜像：MenuTerminal（一条菜单一行，供旧查询兼容）

【运行时层】
  登录 → 租户(RLS) → 终端号 → 菜单 WHERE TerminalType=? → 权限点过滤 → 渲染
```

## 4. 实际形态（V42 之后实测）

### 4.1 功能模块：三层，636 条

| 层级 | 数量 | 含义 | 例子 |
|---|---|---|---|
| Level 1 | 10 | 业务域 | `01 主数据`、`02 采购与供应商` … `10 计划与决策` |
| Level 2 | 62 | 模块 | `0101 组织与门店`、`0102 商品与主数据` … |
| Level 3 | 564 | 功能节点 | `010101`、`070705 PDA拣货复核` … |

- 功能点 1436 条**全部挂在 Level 3**；
- 权限点：`MOD:` 638、`FUN:` 1436、`DATA:` 3、`DESIGN:` 9。

### 4.2 终端可用模块（`plat.ModuleTerminal`）

| 终端 | 模块数 | 菜单数 | 功能点数 |
|---|---|---|---|
| PC | 636 | 678 | 1436 |
| PDA | 29 | 29 | 41 |
| POS | 84 | 84 | 209 |
| 移动 | 130 | 130 | 274 |
| 小程序 | 114 | 114 | 192 |
| 其他 | 68 | 68 | 98 |

### 4.3 菜单：1103 条，每条恰好一个终端

| 终端 | 菜单数 | 说明 |
|---|---|---|
| PC | 678 | 含 42 条平台管理菜单（不绑模块，纯入口/分组） |
| 其他 | 68 | 由原来的「PC + 其他」多终端菜单拆分而来 |
| 移动 | 130 | |
| 小程序 | 114 | |
| POS | 84 | |
| PDA | 29 | |

拆分规则：原来一条菜单挂多个终端的（370+26 条），按终端复制成多条，编码加后缀
`.PDA` / `.POS` / `.MOBILE` / `.MINIAPP` / `.OTHER`，父子关系逐层重挂（V41）。

绑定情况：1061 条绑了模块，42 条没绑（平台管理子树的入口与分组）；绑页面 1 条，其余走 `/m/{code}` 占位。

**越界校验：0 条**（不存在「菜单的模块没在该终端启用」的脏数据）。

## 5. 运行时判定链

```
1. 租户隔离   SESSION_CONTEXT + RLS                     → 只看本租户配置
2. 终端过滤   Menu.TerminalType = 请求的终端号           → 一个终端一棵菜单树
3. 状态过滤   IsDeleted=0 / IsEnabled=1 / IsVisible=1
4. 权限过滤   MOD:xxx / FUN:xxx；叶子无权限则整枝移除，父节点有可见子则保留
5. 路由解析   Route 优先；没 Route 但绑了 Page 用 /m/{code}；都没有 → 点击无反应（需补）
```

菜单点击后可能落到三类页面：

| 目标 | 例子 | 说明 |
|---|---|---|
| 元数据列表页 | `/object/md.brand` | 引擎渲染，真正有功能 |
| 配置界面 | `/design?tab=rule`、`/system/modules` | 设计器/管理窗口 |
| 占位页 | `/m/900202` | 菜单存在、页面未建 |

## 6. 子系统：为什么还缺

方案里的 57 个子系统按「平台 20 / 终端 9 / 业务 10 / 集成 15 / 工程 3」划分，
其中「业务 10」与模块树的 Level 1（10 个业务域）一一对应，其余 47 个是**跨业务域的横向单位**
（如「权限引擎」「打印模板」「CI/CD」），无法用现有模块树表达。

所以当前状态是：

- **业务子系统** = 模块 Level 1（已落地，10 个）；
- **平台/集成/工程子系统** = 没有实体，只在文档里；
- 若要让 57 个子系统都进系统，需要新增 `plat.SubSystem`（Code/Name/Owner/Layer/上线开关）
  并给 `plat.Module` 加 `SubSystemId`——这是架构决策，需负责人拍板后再做。

## 7. 相关接口

| 用途 | 接口 |
|---|---|
| 终端列表与规模 | `GET /api/admin/terminals`、`/overview` |
| 终端已启用模块 | `GET /api/admin/terminals/{t}/modules` |
| 全量模块 + 启用状态 | `GET /api/admin/terminals/{t}/modules/all` |
| 整体替换 | `PUT /api/admin/terminals/{t}/modules` |
| 单个启用/停用 | `POST/DELETE /api/admin/terminals/{t}/modules/{moduleId}` |
| 菜单树（可按终端过滤） | `GET /api/admin/menus/tree?terminalType=` |
| 侧边栏菜单树 | `GET /api/menu/tree?terminal=` |
| 模型关系图（含警告） | `GET /api/admin/modules/model-map` |

界面：`/#/system/terminals`（终端与功能）、`/#/system/menus`（菜单设置）、`/#/system/modules`（功能模块管理）。
